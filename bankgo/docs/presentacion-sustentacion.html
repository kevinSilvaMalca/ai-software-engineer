Flujo de Autenticación PKCE

¿Por qué PKCE en mobile?

  • Las apps mobile no pueden guardar client secrets de forma segura (el APK es descompilable).
  • PKCE (RFC 7636) soluciona esto con un par verifier + challenge derivado criptográficamente.
  • Protege contra ataques de authorization code interception.

Código real de pkce.ts

// generateCodeVerifier — RFC 7636 §4.1 // 32 bytes → 43 chars base64url export async function generateCodeVerifier() { const bytes = Crypto.getRandomBytes(32); return toBase64Url(bytes); // sin padding = } // generateCodeChallenge — RFC 7636 §4.2 // SHA-256 del verifier, base64url-encoded export async function generateCodeChallenge(v) { const digest = await Crypto.digest( Crypto.CryptoDigestAlgorithm.SHA256, new TextEncoder().encode(v), ); return toBase64Url(new Uint8Array(digest)); }

Flujo paso a paso

1
Usuario ingresa email + password

La contraseña nunca se almacena ni loguea

2
generateCodeVerifier() — 32 bytes aleatorios → base64url (43 chars)
3
generateCodeChallenge(verifier) — SHA-256 del verifier → base64url
4
generateState() — 16 bytes → hex string (CSRF token)
5
POST /auth/token con email, password, challenge, state
6
Respuesta: access_token + refresh_token + expires_in (3600s)
7
SecureStore persiste los 3 valores: access, refresh, expires_at
8
tokenStore.setTokens() hidrata la memoria para requests inmediatos

Mock API — Sin necesidad de servidor real

devClient.ts — Para desarrollo en device

En Expo Go, MSW (msw/node) no puede interceptar fetch porque no corre un Service Worker. La solución: reemplazar el apiClient completo con un cliente que sirve los mismos datos sin ninguna llamada de red.

// client.ts — selección automática export const apiClient = typeof __DEV__ !== 'undefined' && __DEV__ && process.env['NODE_ENV'] !== 'test' ? devApiClient // ← device/emulador : httpApiClient; // ← tests (MSW intercepta)

Rutas mock implementadas

  • POST /auth/token
  • GET /auth/me
  • GET /accounts
  • GET /accounts/:id
  • GET /accounts/:id/transactions?page&limit
  • POST /transfers
  • POST /transfers/:id/confirm
  • GET /cards
  • PATCH /cards/:id (toggle frozen)

MSW handlers.ts — Para tests

En el entorno de Jest, el httpApiClient real hace fetch() y MSW lo intercepta a nivel de Node. Los tests ejercitan el código exactamente igual que producción.

// handlers.ts — mismo código en test y dev http.post('/auth/token', async () => { await FAST(); // 200-400ms simulados return HttpResponse.json({ access_token: MOCK_ACCESS_TOKEN, // Never log actual token }); }), http.get('/accounts', async ({ request }) => { if (!requireAuth(request)) return unauthorized(); return HttpResponse.json(seedAccounts); }),

Estado in-memory stateful

Las transferencias y el estado de congelamiento de tarjetas se guardan en Map<string, Transfer> en memoria — sin base de datos, sin servidor, con estado consistente entre requests.

Modo Offline — Cache TTL en AsyncStorage

Cómo funciona el patrón offline-first

1
fetchAccounts() intenta llamada a red vía apiClient
2
Si éxito: escribe en AsyncStorage con TTL de 5 minutos (expiresAt = Date.now() + 300_000)
3
Si falla la red: lee la clave bankgo:accounts de AsyncStorage
4
Si hay cache válido (no expirado): muestra datos + banner isOffline: true
5
Si no hay cache: muestra ErrorState con botón de Retry

TTL por tipo de dato

DatoClave AsyncStorageTTL
Cuentasbankgo:accounts5 minutos
Transaccionesbankgo:transactions:id:page2 minutos

Código real de cacheService.ts

// TTL constants const TTL_ACCOUNTS_MS = 5 * 60 * 1000; // 5 min const TTL_TRANSACTIONS_MS = 2 * 60 * 1000; // 2 min interface CacheEntry<T> { data: T; cachedAt: number; expiresAt: number; // ← el que importa } async get<T>(key: string): Promise<T | null> { const raw = await AsyncStorage.getItem(key); if (raw === null) return null; const entry = JSON.parse(raw) as CacheEntry<T>; if (Date.now() > entry.expiresAt) { await AsyncStorage.removeItem(key); // limpia return null; // ← TTL expirado } return entry.data; }

✓ Validado por test: cache.test.ts verifica que get() retorna null para TTL expirado usando jest.advanceTimersByTime(2000).
