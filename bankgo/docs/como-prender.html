📦 Instalación de dependencias

Cloná el repositorio e instalá las dependencias. El flag --legacy-peer-deps es necesario porque React Native 0.81 y Expo SDK 54 tienen dependencias de peers que chocaron con npm 10.

1
Clonar el repositorio
O navegá a la carpeta si ya tenés el código
Terminal
git clone https://github.com/TU_ORG/ai-software-engineer.git cd ai-software-engineer/bankgo
2
Instalar dependencias
~2-3 minutos la primera vez
Terminal — dentro de bankgo/
npm install --legacy-peer-deps # Alternativamente con yarn: yarn install
⚠ NUNCA usar npm install sin --legacy-peer-deps — el postinstall script (scripts/patch-expo-router.js) también se ejecuta automáticamente.
3
Verificar instalación
Asegurarse de que no hay errores críticos
Verificar type check
npx tsc --noEmit # Resultado esperado: (sin salida = 0 errores)
✓ npx tsc --noEmit sin errores significa que TypeScript compila correctamente.

📱 Levantar el emulador Android

Necesitás un emulador corriendo antes de arrancar Metro para que Expo pueda instalar la app automáticamente.

1
Opción A: desde Android Studio
Más simple para empezar
  • Abrir Android Studio
  • Ir a Device Manager (icono de teléfono en la barra lateral)
  • Buscar el emulador Pixel 7 API 34
  • Hacer click en el botón ▶ (Play) para iniciarlo
  • Esperar a que el emulador cargue completamente (se ve la pantalla de inicio de Android)
2
Opción B: desde la terminal
Para automatizar o scripting
Terminal
# Listar emuladores disponibles emulator -list-avds # Output esperado: Pixel_7_API_34 # Arrancar el emulador específico emulator -avd Pixel_7_API_34 # Si el comando 'emulator' no existe, buscar en: # ~/Android/Sdk/emulator/emulator (Linux/Mac) # %LOCALAPPDATA%\Android\Sdk\emulator\emulator.exe (Windows)
ℹ El emulador tarda entre 30 y 90 segundos en cargar. Esperá a que aparezca la pantalla de inicio de Android antes de continuar.
3
Configurar port forwarding
Necesario para que el emulador alcance Metro en tu máquina
Terminal — con el emulador ya corriendo
adb reverse tcp:8081 tcp:8081 # Output esperado: 8081 # Si no hay output o da error, ver sección Troubleshooting
⚠ Este paso es crítico. Sin adb reverse, el emulador no puede conectarse al servidor Metro que corre en tu máquina. Síntoma: la app abre pero queda en pantalla de carga o muestra "Unable to connect to Metro".

⚡ Arrancar Metro

Metro es el bundler de JavaScript de React Native. Expo lo envuelve con su propio CLI. El comando exacto importa — hay flags específicos que resuelven problemas conocidos en este proyecto.

★
Comando canónico para este proyecto
Usá este exacto — cada flag tiene un motivo
Terminal — dentro de bankgo/
EXPO_OFFLINE=1 npx expo start --host localhost --android
EXPO_OFFLINE=1

Evita que Expo intente conectarse a los servidores de Expo (updates, telemetría). Elimina timeouts de red cuando no hay conexión o cuando hay firewalls.

--host localhost

Fuerza a Metro a usar localhost en vez de la IP de la interfaz de red. Necesario para que adb reverse funcione correctamente en emuladores Android.

--android

Abre directamente el emulador Android detectado. Equivale a presionar 'a' en el menú de Metro después de iniciar.

Resultado esperado

Metro inicia, muestra el QR code, y empieza a instalar la app en el emulador automáticamente.

¿Qué ves en la terminal de Metro?

› Metro waiting on exp://127.0.0.1:8081 › Scan the QR code above with Expo Go (Android) or the Camera app (iOS) (automáticamente busca emulador con --android) › Opening on Android... › Building JavaScript bundle... █████████████████████████████ 100% › Bundle built in 2345ms

⚠ Troubleshooting

Problemas frecuentes que aparecieron durante el desarrollo y sus soluciones exactas.

Metro ya está corriendo en el puerto 8081

Error: listen EADDRINUSE: address already in use :::8081
Causa: Hay una instancia de Metro (u otro proceso) que ya ocupó el puerto 8081. Esto pasa si cerraste Metro con Ctrl+C pero el proceso no terminó limpiamente.
Solución:
# Encontrar el proceso que usa el puerto lsof -i :8081 # Output: node 12345 username 25u IPv6 ... # Matarlo con su PID kill -9 12345 # En Windows: netstat -ano | findstr :8081 taskkill /PID 12345 /F # Alternativa: usar un puerto diferente EXPO_OFFLINE=1 npx expo start --port 8082 --host localhost # Y actualizar adb reverse: adb reverse tcp:8082 tcp:8082

Error: PlatformConstants no disponible

Invariant Violation: Module AppRegistry is not a registered callable module
Causa: Las versiones de React Native 0.81 y Expo SDK 54 habilitaron la New Architecture por defecto. Algunos módulos nativos en el emulador no estaban preparados para JSI (JavaScript Interface), causando fallos al registrar módulos.
Solución: El archivo app.json ya tiene "newArchEnabled": true que en combinación con "edgeToEdgeEnabled": false y "predictiveBackGestureEnabled": false estabiliza el comportamiento. Si el error persiste:
# Limpiar la caché de Metro npx expo start --clear # O con el flag completo EXPO_OFFLINE=1 npx expo start --clear --host localhost --android

Error: getDevServer is not a function

TypeError: (0, _reactNative.NativeModules).DevSettings.getDevServer is not a function
Causa: Expo Router 6.x tiene un conflicto con ciertas versiones de react-native en el entorno de desarrollo. El postinstall script en scripts/patch-expo-router.js parchea esto automáticamente.
Solución: Verificar que el postinstall corrió correctamente:
# Re-ejecutar el postinstall manualmente node scripts/patch-expo-router.js # Si no existe el script, reinstalar desde cero rm -rf node_modules npm install --legacy-peer-deps

adb reverse falla o la app no conecta

error: no devices/emulators found
Causa 1: El emulador no terminó de cargar cuando se ejecutó adb reverse. Causa 2: ADB no está en el PATH del sistema. Causa 3: El emulador está en un estado inconsistente.
Soluciones:
# Verificar que el emulador está visible para adb adb devices # Output esperado: # List of devices attached # emulator-5554 device # Si no aparece, reiniciar el servidor adb adb kill-server adb start-server adb devices # verificar de nuevo # Luego ejecutar reverse adb reverse tcp:8081 tcp:8081 # Output esperado: 8081 # Si sigue fallando, probar con IP explícita EXPO_OFFLINE=1 npx expo start --host 0.0.0.0 --android # Expo intentará usar la IP local de tu máquina
La app abre pero queda en "Fetching JavaScript bundle..."
Causa: El emulador no puede alcanzar Metro. Típicamente es que adb reverse no se ejecutó o se ejecutó antes de que el emulador estuviera listo.
Solución: Con el emulador visible en pantalla y Metro corriendo:
adb reverse tcp:8081 tcp:8081 # Luego sacudir el emulador (Cmd+M o Ctrl+M) para abrir el menú Expo # → "Reload"
